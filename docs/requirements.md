# Campus AR API - 要件定義書

## 1. プロジェクト概要
Campus AR は、大学のキャンパス内で学生や訪問者に対して、位置情報に基づくARコンテンツ（案内、イベント情報、バーチャル展示など）を提供するサービスです。
`campus-ar-api` はそのバックエンドシステムとして機能します。

## 2. 目的
*   ARクライアントアプリへの高速かつ安定したデータ提供。
*   Cloudflare Workersのエッジコンピューティングを活用した低遅延なAPIの実現。
*   SupabaseおよびCloudflare R2を活用した、スケーラブルなデータおよびアセット管理。

## 3. 機能要件

### 3.1. 認証機能
<!-- *   Supabase Authを利用したユーザー認証（サインアップ、ログイン、ログアウト）。　 -->
*   API側でのJWT検証による保護されたエンドポイントの提供。

### 3.2. スポット（POI）管理
*   キャンパス内の建物や特定地点（POI: Point of Interest）の情報を取得できること。
*   位置情報（緯度・経度）に基づき、ユーザーの周辺にあるスポットを検索できること。

### 3.3. ARコンテンツ・アセット管理
*   各スポットに紐づくARコンテンツ（テキスト、画像、3Dモデル）のメタデータを取得できること。
*   Cloudflare R2に保存された3DモデルファイルへのアクセスURL（または署名付きURL）を提供できること。

### 3.4. イベント・通知管理
*   現在開催中、または予定されているキャンパス内のイベント情報を取得できること。

### 3.5. ユーザーインタラクション
*   ユーザーが特定のスポットを訪問した（ARコンテンツを閲覧した）履歴を保存できること。
*   スタンプラリー等の機能のための進行状況の保存。

## 4. 非機能要件
*   **パフォーマンス:** エッジワーカー（Cloudflare Workers）上で動作するため、コールドスタートが遅くならないように設計する。
*   **スケーラビリティ:** トラフィックのスパイクに対してCloudflareインフラにより自動でスケールすること。
*   **セキュリティ:** DBへのアクセスは必要最小限の権限（RLS）で行い、APIキーなどのシークレットはWorkersの環境変数（Secrets）で管理する。
*   **可用性:** CloudflareおよびSupabaseのSLAに準拠する。
